Below is a simplified example of what the MCP server might look like. This example uses `stdio` for simplicity, but you would likely use `StreamableHTTP` or `SSE` for a production web service.

**Filename: `mcp-core-api-server.ts`**

```ts
import {
  Server,
  StdioServerTransport,
  createJSONRPC10Server,
} from '@modelcontextprotocol/sdk/server';
import {
  CallToolRequestSchema,
  ListToolsRequestSchema,
  ListToolsResultSchema,
  CallToolResultSchema,
} from '@modelcontextprotocol/sdk/types';
import { z } from 'zod';

// Define the tools your MCP server will expose.
// These tools map directly to functions/endpoints in your Core API.
const CORE_API_TOOLS = {
  searchArticles: {
    description: 'Search for articles in the Core API by keyword or topic.',
    inputSchema: z.object({
      query: z.string().describe('The search term or phrase.'),
      limit: z.number().optional().default(10).describe('Maximum number of results to return.'),
    }),
  },
  getUserProfile: {
    description: 'Retrieve a user profile by their unique ID.',
    inputSchema: z.object({
      userId: z.string().describe('The unique identifier of the user.'),
    }),
  },
  createDocument: {
    description: 'Create a new document in the Core API.',
    inputSchema: z.object({
      title: z.string().describe('The title of the document.'),
      content: z.string().describe('The main content of the document.'),
      tags: z.array(z.string()).optional().describe('Tags associated with the document.'),
    }),
  },
  // Add more tools here as needed for other Core API endpoints
} as const;

// Function to execute a tool call by making an actual HTTP request to your Core API
async function executeCoreAPITool(toolName: string, args: any): Promise<any> {
  const baseUrl = process.env.CORE_API_BASE_URL || 'https://api.your-core-api.com';
  const apiKey = process.env.CORE_API_KEY; // If your API requires authentication

  let url: string;
  let method: string = 'GET';
  let body: any = undefined;

  // Map the MCP tool name to the actual Core API endpoint and method
  switch (toolName) {
    case 'searchArticles':
      url = `${baseUrl}/v1/articles/search`;
      url += `?q=${encodeURIComponent(args.query)}&limit=${args.limit || 10}`;
      break;
    case 'getUserProfile':
      url = `${baseUrl}/v2/users/${encodeURIComponent(args.userId)}`;
      break;
    case 'createDocument':
      url = `${baseUrl}/v1/documents`;
      method = 'POST';
      body = {
        title: args.title,
        content: args.content,
        tags: args.tags,
      };
      break;
    default:
      throw new Error(`Unknown tool: ${toolName}`);
  }

  const fetchOptions: RequestInit = {
    method,
    headers: {
      'Content-Type': 'application/json',
      ...(apiKey ? { Authorization: `Bearer ${apiKey}` } : {}),
    },
  };

  if (body) {
    fetchOptions.body = JSON.stringify(body);
  }

  try {
    const response = await fetch(url, fetchOptions);

    if (!response.ok) {
      const errorText = await response.text();
      throw new Error(`Core API Error (${response.status}): ${errorText}`);
    }

    return await response.json();
  } catch (error) {
    // It's important to throw an error so the MCP client can handle it
    // and the AI SDK can convert it into a 'tool-error' for the LLM.
    throw error;
  }
}

// Create the MCP Server instance
const server = new Server(
  {
    name: 'core-api-mcp-server',
    version: '1.0.0',
  },
  {
    capabilities: {
      tools: {},
    },
  }
);

// Handle the 'tools/list' request from the MCP client.
// This tells the AI agent what tools are available.
server.setRequestHandler(ListToolsRequestSchema, async () => {
  const tools = Object.entries(CORE_API_TOOLS).map(([name, tool]) => ({
    name,
    description: tool.description,
    inputSchema: tool.inputSchema,
  }));

  return ListToolsResultSchema.parse({
    tools,
  });
});

// Handle the 'tools/call' request, which is triggered when the LLM wants to use a tool.
server.setRequestHandler(CallToolRequestSchema, async (request) => {
  const { name: toolName, arguments: args } = request.params;

  if (!CORE_API_TOOLS[toolName as keyof typeof CORE_API_TOOLS]) {
    throw new Error(`Tool not found: ${toolName}`);
  }

  // Execute the tool by calling the Core API
  const result = await executeCoreAPITool(toolName, args);

  return CallToolResultSchema.parse({
    content: result,
  });
});

// Create a JSON-RPC server and connect it to stdio
const jsonRpcServer = createJSONRPC10Server();
const transport = new StdioServerTransport(process.stdin, process.stdout);
jsonRpcServer.setTransport(transport);

// Connect the MCP server to the JSON-RPC server
server.connect(jsonRpcServer);

console.log('MCP Server for Core API is running...');
```

### 2. Use the MCP Server in Your AI Agent (Client-Side)

Once your MCP server is running, you can connect to it from your AI agent using the Vercel AI SDK's `experimental_createMCPClient`.

**Filename: `ai-agent-with-mcp.ts`**

```ts
import { experimental_createMCPClient as createMCPClient } from 'ai';
import { generateText, stepCountIs } from 'ai';
import { openai } from '@ai-sdk/openai';
import { StreamableHTTPClientTransport } from '@modelcontextprotocol/sdk/client/streamableHttp';

export async function askAgentWithCoreAPITools(userQuery: string) {
  // Create an MCP client that connects to your MCP server
  // Replace the URL with where your MCP server is hosted
  const mcpTransport = new StreamableHTTPClientTransport(
    new URL('http://localhost:4000/mcp') // Your MCP server endpoint
  );

  const mcpClient = await createMCPClient({
    transport: mcpTransport,
  });

  try {
    // Retrieve the tools from the MCP server
    // You can optionally pass a `schemas` object here for type safety,
    // but for simplicity, we let the client infer the schemas from the server.
    const coreAPITools = await mcpClient.tools();

    // Use the tools in a multi-step generation
    const result = await generateText({
      model: openai('gpt-4o'),
      tools: coreAPITools,
      stopWhen: stepCountIs(5), // Allow up to 5 steps for complex queries
      system: 'You are a helpful assistant that can search for articles, retrieve user profiles, and create documents using the provided tools. Always use a tool when relevant to answer the user.',
      prompt: userQuery,
    });

    return result.text;
  } finally {
    // Always close the MCP client to free up resources
    await mcpClient.close();
  }
}

// Example usage
const answer = await askAgentWithCoreAPITools(
  'Find me 5 articles about climate change and then create a summary document titled "Climate Change Overview".'
);
console.log(answer);
```

3.  **Dynamic Discovery**: The AI agent dynamically discovers available tools at runtime by calling `mcpClient.tools()`. This means you can add or remove tools from the MCP server without redeploying your agent.
4.  **Error Handling**: Errors from the Core API are caught in the MCP server and thrown. The AI SDK will automatically convert these into `tool-error` parts, allowing the LLM to attempt recovery in a multi-step scenario.
5.  **Standards-Based**: You're using the emerging MCP standard, making your tools potentially reusable with other MCP-compatible clients in the future.
6.  **Vercel AI SDK Compliant**: The client-side code uses `experimental_createMCPClient` and integrates seamlessly with `generateText` and `streamText`, including multi-step calls and error handling as per the documentation.

This setup effectively turns your Core API into a toolbox that any AI agent, built with the Vercel AI SDK, can use intelligently.

```ts
async function coreApiRequest<T>(
  endpoint: string,
  options: RequestInit = {}

  const url = `${CORE_API_BASE_URL}${endpoint}`;
  const headers = new Headers(options.headers);

    }),
  },
  aggregateOutputs: {
    description: 'Get aggregated statistics for outputs matching a search query.',
    inputSchema: z.object({
      q: z.string().describe('The search query.'),
      aggregations: z.array(z.string()).describe('List of fields to aggregate by (e.g., ["documentType", "language"]).'),
    }),
  },

  // --- MISCELLANEOUS ---
  discoverFullText: {
    description: 'Find full-text links for a document based on its DOI, title, and year.',
    inputSchema: z.object({
      doi: z.string().describe('The DOI of the document.'),
      title: z.string().describe('The title of the document.'),
      year: z.number().describe('The publication year.'),
    }),
  },
  getRecommendations: {
    description: 'Get recommendations for related scholarly records based on text or an identifier.',
    inputSchema: z.object({
      text: z.string().optional().describe('The text to base recommendations on.'),
      identifier: z.string().optional().describe('The Core ID of a record to base recommendations on.'),
      limit: z.string().optional().default('10').describe('Number of recommendations to return.'),
    }).refine(data => data.text || data.identifier, {
      message: "Either 'text' or 'identifier' must be provided.",
    }),
  },
} as const;

// Function to execute a tool call by mapping it to the actual Core API endpoint
async function executeCoreAPITool(toolName: keyof typeof CORE_API_MCP_TOOLS, args: any): Promise<any> {
  try {
    switch (toolName) {
      // WORKS
      case 'searchWorks':
        return await coreApiRequest(`/search/works`, {
          method: 'POST',
          body: JSON.stringify(args),
        });
      case 'getWorkById':
        return await coreApiRequest(`/works/${encodeURIComponent(args.identifier)}`);
      case 'getWorkOutputs':
        return await coreApiRequest(`/works/${encodeURIComponent(args.identifier)}/outputs?limit=${args.limit}&offset=${args.offset}`);
      case 'downloadWorkFile':
        // For file downloads, we return the URL so the client can handle it.
        // Alternatively, you could return a base64 string, but that's heavy for MCP.
        return { downloadUrl: `${CORE_API_BASE_URL}/works/${encodeURIComponent(args.identifier)}/download` };

      // OUTPUTS
      case 'searchOutputs':
        return await coreApiRequest(`/search/outputs`, {
          method: 'POST',
          body: JSON.stringify(args),
        });
      case 'getOutputById':
        return await coreApiRequest(`/outputs/${encodeURIComponent(args.identifier)}`);
      case 'downloadOutputFile':
        return { downloadUrl: `${CORE_API_BASE_URL}/outputs/${encodeURIComponent(args.identifier)}/download` };

      // DATA PROVIDERS
      case 'searchDataProviders':
        return await coreApiRequest(`/search/data-providers`, {
          method: 'POST',
          body: JSON.stringify(args),
        });
      case 'getDataProviderById':
        return await coreApiRequest(`/data-providers/${encodeURIComponent(args.identifier)}`);
      case 'searchDataProviderOutputs':
        const { dataProviderId, ...queryParams } = args;
        const searchParams = new URLSearchParams(queryParams as Record<string, string>);
        return await coreApiRequest(`/data-providers/${encodeURIComponent(dataProviderId)}/outputs?${searchParams.toString()}`);

      // JOURNALS
      case 'searchJournals':
        return await coreApiRequest(`/search/journals`, {
          method: 'POST',
          body: JSON.stringify(args),
        });
      case 'getJournalById':
        return await coreApiRequest(`/journals/${encodeURIComponent(args.identifier)}`);

      // AGGREGATIONS
      case 'aggregateWorks':
        return await coreApiRequest(`/search/works/aggregate`, {
          method: 'POST',
          body: JSON.stringify(args),
        });
      case 'aggregateOutputs':
        return await coreApiRequest(`/search/outputs/aggregate`, {
          method: 'POST',
          body: JSON.stringify(args),
        });

      // MISCELLANEOUS
      case 'discoverFullText':
        return await coreApiRequest(`/discover`, {
          method: 'POST',
          body: JSON.stringify(args),
        });
      case 'getRecommendations':
        return await coreApiRequest(`/recommend`, {
          method: 'POST',
          body: JSON.stringify(args),
        });

      default:
        throw new Error(`Unknown tool: ${toolName}`);
    }
  } catch (error) {
    // It's crucial to throw the error so the MCP client can handle it
    // and the Vercel AI SDK can convert it into a 'tool-error' for the LLM.
    throw error;
  }
}

// Create the MCP Server
const server = new Server(
  {
    name: 'core-api-mcp-server',
    version: '1.0.0',
  },
  {
    capabilities: {
      tools: {},
    },
  }
);

// Handle 'tools/list' request: Tell the client what tools are available.
server.setRequestHandler(ListToolsRequestSchema, async () => {
  const tools = Object.entries(CORE_API_MCP_TOOLS).map(([name, tool]) => ({
    name,
    description: tool.description,
    inputSchema: tool.inputSchema,
  }));

  return ListToolsResultSchema.parse({
    tools,
  });
});

// Handle 'tools/call' request: Execute the tool when the LLM calls it.
server.setRequestHandler(CallToolRequestSchema, async (request) => {
  const { name: toolName, arguments: args } = request.params;

  if (!CORE_API_MCP_TOOLS[toolName as keyof typeof CORE_API_MCP_TOOLS]) {
    throw new Error(`Tool not found: ${toolName}`);
  }

  // Execute the tool by calling the Core API
  const result = await executeCoreAPITool(toolName as keyof typeof CORE_API_MCP_TOOLS, args);

  return CallToolResultSchema.parse({
    content: result,
  });
});

// Set up JSON-RPC server and connect it to stdio (for local testing)
const jsonRpcServer = createJSONRPC10Server();
const transport = new StdioServerTransport(process.stdin, process.stdout);
jsonRpcServer.setTransport(transport);
server.connect(jsonRpcServer);

console.log('✅ Core API MCP Server is running and ready to accept connections.');
```

### **Step 3: Create a Client Script to Test the MCP Server (`test-mcp-client.ts`)**

This script uses the Vercel AI SDK to connect to your local MCP server and demonstrates how an AI agent can use the Core API tools.

```ts
// test-mcp-client.ts
import { experimental_createMCPClient as createMCPClient } from 'ai';
import { generateText, stepCountIs } from 'ai';
import { openai } from '@ai-sdk/openai';
import { Experimental_StdioMCPTransport } from 'ai/mcp-stdio';

async function main() {
  // Initialize the MCP client to connect to our local stdio server
  const mcpTransport = new Experimental_StdioMCPTransport({
    command: 'npx',
    args: ['ts-node', 'core-api-mcp-server.ts'], // Points to your MCP server file
  });

  const mcpClient = await createMCPClient({
    transport: mcpTransport,
  });

  try {
    // Fetch all tools from the MCP server
    const coreTools = await mcpClient.tools();

    console.log('🔍 Available Core API Tools:', Object.keys(coreTools));

    // Use the tools in a multi-step AI generation
    const result = await generateText({
      model: openai('gpt-4o'),
      tools: coreTools,
      stopWhen: stepCountIs(5), // Allow up to 5 steps for complex queries
      system: `You are a scholarly research assistant with access to the Core API.
      Use the provided tools to find the most relevant and up-to-date information.
      Always cite the source (e.g., work ID or output ID) when presenting results.`,
      prompt: `Find 3 recent (published after 2023) research papers about "Large Language Models in Education".
      For one of them, also find its source-specific outputs and tell me which repository it came from.`,
    });

    console.log('\n📝 Final Answer from AI Agent:');
    console.log(result.text);

    // Optionally, log all steps for debugging
    console.log('\n📊 Execution Steps:');
    result.steps.forEach((step, index) => {
      console.log(`\n--- Step ${index + 1} ---`);
      if (step.toolCalls.length > 0) {
        step.toolCalls.forEach(tc => console.log(`🛠️  Tool Call: ${tc.toolName}`, tc.input));
      }
      if (step.toolResults.length > 0) {
        step.toolResults.forEach(tr => console.log(`✅ Tool Result:`, tr.result));
      }
      if (step.text) {
        console.log(`💬 AI Response: ${step.text}`);
      }
    });

  } finally {
    // Always close the MCP client to free up resources
    await mcpClient.close();
  }
}

// Run the test
main().catch(console.error);
```

### **Why This Implementation is Compliant and Effective**

1.  **MCP Standard Compliance**: The server implements the MCP protocol using the official SDK, making it interoperable with any MCP client, not just Vercel's.
2.  **Core API Coverage**: It exposes a comprehensive set of functions covering all major entities (Works, Outputs, Data Providers, Journals) and operations (search, get, aggregate, download).
3.  **Vercel AI SDK Ready**: The client-side code uses `experimental_createMCPClient` and integrates seamlessly with `generateText`, including multi-step execution and error handling.
4.  **Error Handling**: Errors from the Core API are thrown in the server, which the AI SDK will convert into `tool-error` parts, allowing the LLM to attempt recovery.
5.  **Scalable Architecture**: By separating the MCP server from the AI agent, you can scale, update, or secure the Core API integration independently.
6.  **Type Safety**: Although MCP tools are dynamic, the server defines clear Zod schemas, which can be mirrored on the client for full type safety if desired.

This setup transforms the Core API into a powerful, standardized toolbox that any AI agent built with the Vercel AI SDK can leverage to perform sophisticated scholarly research.
